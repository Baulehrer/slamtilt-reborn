- The 105592-byte `Game.exe` is identical across TOSEC retail disk 1, DLM, DLM-alt, 68040-labelled disk 1, Delirium, JST and both CD32 distributions. Therefore the 68040 change is outside this executable; compare other payloads and boot files.
- WHDLoad Full `Game.exe` is RNC/PRO-PACK method 1 (44869 bytes), not directly comparable executable code. BTTR-HD is a smaller loadseg binary, probably runtime packed; unpack before semantic comparison.
- Original Amiga demo `Demo.Exe` is identical across AP60, AA83, Aminet and the duplicate WHD demo source archive. WHDLoad's preinstalled demo is RNC/PRO-PACK.
- Windows Demo RAR and both CD Gamer executable copies are identical. UK retail and CloneCD ROM are identical. US retail and RIP are identical.
- Windows compatibility fix is exactly one byte against UK/ROM at file offset `0xe356`. Mapping the opcode and its containing routine has exceptionally high value.
- EU `SLAMTILT.EXE` is an InstallShield 3 setup wrapper, **not** the game executable. Its linker/build date cannot be compared as a game revision. Extract installed payload next.
- The 1999 image contains SlamTilt Resurrection / STR Demon, a separate product. It is not evidence of an original-game 1999 engine revision.

## Interpretation limits and next actions

Aligned block matching can detect unchanged and shifted byte regions, but misses shifts not divisible by 32 and cannot classify code/data without section analysis. Relocations and addresses break exact matching. Unmatched blocks are only changed/added/removed candidates. No routine equivalence is claimed. First normalize RNC and runtime-packed Amiga binaries; then compare executable hunks and Windows executable sections with relocation-normalized instruction streams. Resolve EU InstallShield payload and DC-STFIX DMS before investing in their wrappers.
